# Audit fixes — October 2026

What changed, and what to do when you update a running server.

## Before you update a server

- **Migration 032** runs with `npm run db:migrate` (new table `action_locks`, columns `orders.ext_order_id`,
  `orders.returning_at`, `profiles.token_version`, `complaints.exchange_back`).
- **JWT_SECRET**: the server refuses the example value in production. `docker compose` now needs `JWT_SECRET` in a `.env`
  file next to `docker-compose.yml`.
- **TRUST_PROXY**: behind nginx / Caddy / a load balancer set `TRUST_PROXY=1`, or the login limit sees every user as the
  proxy (the server logs a warning when this happens).
- **Meta webhooks** are ignored until the Meta app secret is set (Message AI agent › Réglages).
- `seed:demo` is refused when `NODE_ENV=production` (set `ALLOW_DEMO_SEED=1` only on a test server).
- Changing a password (or an admin reset / deactivation) logs that account out everywhere else.

## Fixes

**Permissions** — the offline sync (`orders.sync`) checks the same rights as the screens; a livreur can no longer put his
parcel (and its cash) on another livreur; deleting an account with a money history empties and closes it instead of
erasing the trail (refused while parcels or cash are in hand); the dollar rate is set by the owner only; marketer-only
accounts read no customer data; constant-time webhook keys; secure Dellal verify token; login limit counts failures per
address and per account.

**Money** — couriers without an API get their fee from their tariff when the parcel leaves; a ZR payment import is
atomic, runs once at a time, and leaves out parcels already received by hand; caisse transfers are locked (no double
emptying); month totals are summed in the database; supplier payments leave a caisse (an employee's own caisse);
amount / address are frozen once a parcel is at an API courier or cashed (use « Modifier le colis »).

**Stock** — stock leaves on the first status that means the parcel left (not only « Expédiée »); an SAV exchange puts
back only the exchanged lines (nothing for parts) and only once; shipping into negative stock is noted on the order.

**Order flow** — finished orders change only by suivi / admin with a reason, and a cashed delivery stays delivered; a
re-confirmed order goes back to « À préparer »; confirming needs the commune; the courier sync keeps the suivi's alerts;
double clicks no longer send a parcel, a claim, an exchange or a modification twice; « Commande suivante » never gives
two agents the same customer; website orders sent again are not duplicated (`order_id` in the webhook body); phones like
`+213 0661…` are accepted; courier tracking errors are shown after a sync; « Retours » stats use the day the return
started; the confirmation count no longer includes orders cancelled afterwards.
